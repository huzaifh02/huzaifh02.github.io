Three production environments, one cluster: node-pool isolation with taints and tolerations

Isolated three broad production environments that share one EKS/GKE cluster at the compute layer, so a noisy deployment in one cannot starve another, without paying for three control planes.

Context

Three broad production environments shared a single cluster for cost and operational simplicity. Namespaces separated them logically, but at the node level they competed for the same CPU and memory.

Problem

Namespace boundaries do not stop resource contention on a shared node. A critical customer's workload needed guaranteed capacity, and separate clusters would have multiplied control planes, networking, dashboards and upgrade work.

What I did

  1. Dedicated node pools per environment, defined in Terraform. Each has a unique label and a NoSchedule taint such as environment=env1.
  2. A primary pool with no taints for system pods (CoreDNS, networking, autoscaler), so cluster infrastructure never competes with application load.
  3. Deployments get a node selector plus a matching toleration. The selector points the pod at its pool and the toleration lets it land there. Pods without the toleration are kept out.
  4. Wildcard tolerations for DaemonSets (operator: Exists for NoSchedule and NoExecute), so Fluent Bit and the metrics agents still run on every node.
  5. Sizing per pool from peak load plus 20-30% headroom for evictions and rolling updates, with autoscaling per pool.
nodeSelector:
  environment: env1
tolerations:
  - key: environment
    operator: Equal
    value: env1
    effect: NoSchedule

Impact

  • Environments no longer affect each other's performance, and critical workloads get predictable capacity.
  • One control plane, one set of networking and observability, and one CI/CD context.
  • About 40-60% cheaper than running a cluster per environment.

What I would do differently

Enforce the selector and toleration pair with an admission policy such as Kyverno or Gatekeeper, rather than relying on chart conventions. Then a missing toleration fails at deploy time instead of leaving a pod stuck in Pending.
