1e:T87e,<h2>Context</h2>
<p>Three broad production environments shared a single cluster for cost and operational simplicity. Namespaces separated them logically, but at the node level they competed for the same CPU and memory.</p>
<h2>Problem</h2>
<p>Namespace boundaries do not stop resource contention on a shared node. A critical customer's workload needed guaranteed capacity, and separate clusters would have multiplied control planes, networking, dashboards and upgrade work.</p>
<h2>What I did</h2>
<ol>
<li><strong>Dedicated node pools per environment</strong>, defined in Terraform. Each has a unique label and a <code>NoSchedule</code> taint such as <code>environment=env1</code>.</li>
<li><strong>A primary pool with no taints</strong> for system pods (CoreDNS, networking, autoscaler), so cluster infrastructure never competes with application load.</li>
<li><strong>Deployments get a node selector plus a matching toleration.</strong> The selector points the pod at its pool and the toleration lets it land there. Pods without the toleration are kept out.</li>
<li><strong>Wildcard tolerations for DaemonSets</strong> (<code>operator: Exists</code> for <code>NoSchedule</code> and <code>NoExecute</code>), so Fluent Bit and the metrics agents still run on every node.</li>
<li><strong>Sizing per pool</strong> from peak load plus 20-30% headroom for evictions and rolling updates, with autoscaling per pool.</li>
</ol>
<pre><code class="language-yaml">nodeSelector:
  environment: env1
tolerations:
  - key: environment
    operator: Equal
    value: env1
    effect: NoSchedule
</code></pre>
<h2>Impact</h2>
<ul>
<li>Environments no longer affect each other's performance, and critical workloads get predictable capacity.</li>
<li>One control plane, one set of networking and observability, and one CI/CD context.</li>
<li>About 40-60% cheaper than running a cluster per environment.</li>
</ul>
<h2>What I would do differently</h2>
<p>Enforce the selector and toleration pair with an admission policy such as Kyverno or Gatekeeper, rather than relying on chart conventions. Then a missing toleration fails at deploy time instead of leaving a pod stuck in Pending.</p>
